Summary

This page encrypts and decrypts a short message two ways and then breaks both. The first scheme is EC-ElGamal on the real secp256k1 curve, built on the scalar multiplication Q = kG from exercise 1.1: each letter becomes a curve point, the sender masks it with the public key and a fresh random number, and the holder of the private key k peels the mask off. The second is the Caesar cipher, which just shifts every letter by a fixed amount. I describe each algorithm, the role of its keys, and how the two differ in their procedures, key spaces and statistics.

Both are then attacked. Caesar is broken by statistics: for each of the 26 shifts I score how English the decryption looks and keep the best one, using letter, bigram and trigram counts from eight public-domain books (… letters). Tested on a book by an author the reference never saw, the χ² test on letter frequencies needs … letters to recover the key 90% of the time and trigram scoring only …; from … letters on, every method is right at least 97% of the time (the study runs when the page opens). Very short texts, texts in another language and random letters make it fail, and the page shows each case live. The toy EC scheme is broken not by statistics but by its small key space: the homework restricts k to a small range, so trying every value recovers it in seconds, and baby-step giant-step does it in a fraction of that. The same search over a full 256-bit key space would need about 10⁷⁷ steps, far longer than the age of the universe. On the toy curve from exercise 1.1 I also found a weakness that no key range explains: with k = 6 the public key has order 3, so the encryption mask takes only three values, and one of them leaves the letter in clear.

What surprised me most: the two attacks look similar but rest on opposite facts. Breaking Caesar needs the plaintext to carry language structure, so it fails on random-looking text; breaking the toy curve needs nothing about the message at all, only a key that is small enough to enumerate. Making k large removes the second attack completely, while no key length can save Caesar.

Encrypt a message with the elliptic-curve scheme

The scalar multiplication Q = kG from exercise 1.1, now used to hide a message. This is EC-ElGamal on the real secp256k1 curve, with k kept in a small range so the later attack is feasible.

Keys and point mapEncrypt and decryptThe algorithm, step by step
A toy scheme, on purpose. This encrypts one short message to show the idea, exactly as the homework asks. It is not a real cryptographic system: there is no authentication, the point map is simplistic, and the private key is kept small. Never use it to protect anything real.

The keys and how a letter becomes a point

The public parameters are the secp256k1 curve y² = x³ + 7 and the base point G, the same ones exercise 1.1 used in its bonus section. The private key is a number k; the public key is the point Q = kG. Anyone can encrypt with Q, but only the holder of k can decrypt. To hide the whole alphabet rather than one number, each byte of the message is turned into a point on the curve: the byte value fixes most of the x coordinate and a few spare bits are tried until x³ + 7 is a square, which gives a valid point Pm. The map is reversible, so the point can be read back as a byte.

public key   Q = k·G   (known to everyone)
encrypt letter   Pm → ( C1, C2 ) = ( r·G,   Pm + r·Q )   (fresh random r each letter)
decrypt   Pm = C2 − k·C1

Decryption works because k·C1 = k·(r·G) = r·(k·G) = r·Q, the exact mask that was added, so subtracting it leaves Pm. The attacker sees Q and C1 but cannot find r·Q without either r or k, and recovering k from Q is the discrete-logarithm problem from exercise 1.1.

The Caesar cipher

The oldest substitution cipher: shift every letter forward by a fixed number of places, wrapping Z around to A. The key is that single number.

Encryption adds the shift to each letter's position mod 26; decryption subtracts it. Non-letters are left untouched. There are only 25 useful keys (a shift of 0 does nothing), which is what makes it so weak. Named after Julius Caesar, who, according to Suetonius, shifted his private letters by three.

encrypt   c = ( m + s ) mod 26     decrypt   m = ( c − s ) mod 26
where letters A…Z are numbered 0…25 and s is the key (the shift)

3

Comparing the two schemes

Same job, very different machinery. How they encrypt and decrypt, how large their key spaces are, and what their ciphertexts look like statistically.

What they have in common

Both are reversible with a key: the holder of the right key turns the ciphertext back into exactly the original message, and without it the message should stay hidden. Both work symbol by symbol, one letter at a time, and in both the algorithm is public while the security rests entirely on keeping the key secret (Kerckhoffs's principle). Both can therefore be attacked by searching the key space, and each is only as strong as that space is large. In the demo they even encrypt the same message, so the two ciphertexts can be compared directly.

What the ciphertexts look like

Caesar's bars are the English letter shape, slid sideways by the key. The EC scheme outputs points, not letters, so each point C2 is turned into a letter by taking its x coordinate mod 26; those counts sit flat, like noise. The index of coincidence is the probability that two letters picked at random from a text are the same letter. A Caesar shift only renames letters, so it cannot change this number: the ciphertext keeps the value of English, whatever the key. The EC ciphertext drops to about 1/26, the value for letters drawn uniformly at random. The two χ² tests say the same thing in the language of hypothesis testing: uniformity is rejected for Caesar and not rejected for the EC scheme.

Comparing the attack methods

The optional part of the homework asks to compare approaches. Five are built in. All of them try the 26 shifts and differ only in how they judge a decryption.

Exhaustive key search with a word listTry all 26 shifts and count how many letters fall inside dictionary words. This is the automated version of "print all 26 and let a person read them". The list holds the 2,000 most common words of the reference books, which cover … of the words in the test book; names and rarer words are missing.
Letter-frequency analysis (χ²)Compare the decryption's letter counts with English using a χ² distance; the smallest wins. Fast, and it needs no word list, but it ignores the order of letters.
Letter log-likelihoodThe same letter counts, scored as the probability of the decryption under English letter frequencies: Σ log p of each letter. It is the maximum-likelihood choice of key, and it copes better than χ² with rare letters (see the Italian test below).
Bigram scoringAdd up the log-probability of every pair of neighbouring letters. It uses spelling patterns such as "th" and "qu", so it works on shorter text.
Trigram scoringThe same with triples of letters. It uses more context, but each triple is rarer, so it needs more reference text to be reliable.

Limitations: when the attack fails

The attack assumes the plaintext looks like the reference language. These live tests shift every text by each of the 25 possible keys and count how many keys each method recovers. Very short texts, texts with unusual letter use and random letters are where the assumption breaks.

TextLettersχ²Log-lik.Word listBigramTrigram

Each cell counts how many of the 25 keys the method recovered. Every method tries all 26 shifts, so its verdict on a given text does not depend on which key encrypted it: a method reads a text under every key or under none, which is why the cells are almost always 25/25 or 0/25. The control row works for every method. "Hello" is too short for the χ² test, and the word list does not contain it, but log-likelihood and the n-gram methods read it. "Attack at dawn" defeats the word list because "attack" and "dawn" are not among the 2,000 most common words of the reference books. The pangram has an unusual letter profile that misleads the χ² test. "Veni, vidi, vici" defeats both frequency methods: a quarter of its twelve letters are v and almost half are i, far from the English profile (under 1% and about 7%). The n-gram methods still read it. The Italian line defeats χ² because of the double z in "mezzo", a letter English almost never uses: with "messo" in its place, χ² recovers every key. On the longer Latin and Italian lines the n-gram methods succeed, because the right shift gives the most language-like text even if it is not English, while the word list fails because it only knows English words. Random letters carry no language structure, so no method can do better than a lucky guess (about 1 in 26).

Why χ² suffers more than log-likelihood. The χ² distance divides each squared difference by the expected count N·pⱼ. English expects almost no z or q, but Italian uses them (mezzo, cinque, questo), so a single z adds a huge term and pushes the right shift down the ranking. This is the usual warning about χ² when expected counts are small. Log-likelihood only adds log pⱼ for each letter, so a rare letter costs a bounded penalty and the right shift still wins.

5

Breaking the toy EC scheme

No statistics this time. The homework restricted the private key to a small range, so the attack simply tries every value until kG matches the public key, and then decrypts the message.

Run the attackCost vs key rangeWhy a real curve is safe

The attacker knows the public key Q and the ciphertext, and knows the design: k lies somewhere in [1, M) for a small M. So it walks G, 2G, 3G, …, comparing each against Q. Because consecutive multiples differ by one point addition, the whole range costs one addition per key, with no multiplication per guess. The moment a match appears, the loop has found k, and with k the message decrypts just like the legitimate recipient's.

Why the same attack fails on a real curve

The attack has nothing to do with the message and everything to do with the key range. On secp256k1 a real private key is drawn from the whole group, up to n ≈ 1.16 × 10⁷⁷. At the few hundred thousand keys per second this page manages, and even at a billion times that on special hardware, the search would still run for far longer than the age of the universe.

1.16 × 10⁷⁷keys on the real curve (group order n)
The difference from the Caesar attack. Breaking Caesar reads the plaintext's language structure, so it needs a known language and enough text, and fails on short or random-looking messages. Breaking the toy curve reads nothing from the message; it only needs the key to be small enough to enumerate. Enlarging the key fixes the second attack completely. Nothing fixes Caesar, because its key space is tiny no matter what.

A square-root attack: baby-step giant-step

Brute force tries every key, costing M steps. Baby-step giant-step trades memory for time: it stores √M small multiples of G in a table, then takes √M giant strides through Q until one lands in the table. It finds the key in about 2√M steps instead of M. The same square-root scaling is why a 256-bit curve offers about 128 bits of security: the best generic attack (Pollard's rho, which needs almost no memory) takes about √n steps. Here it recovers the same key in a fraction of the brute-force time.

A weak key on the exercise 1.1 curve

The toy curve from exercise 1.1 shows a weakness that has nothing to do with the size of the key range. On y² = x³ + 7 (mod 17) the base point G = (1, 5) has order 9, and the key k = 6 gives the public key Q = 6G = (5, 8), a point of order 3. In EC-ElGamal the mask added to each letter is rQ, and a point of order 3 has only three multiples: Q, 2Q and the point at infinity O. The table runs through every possible r.

Whenever the mask is O, C₂ = Pₘ + O = Pₘ and the letter travels in clear. For the other values an attacker needs neither k nor r: there are only two other masks, so subtracting each of them from C₂ leaves just two candidates for Pₘ. The cause is the curve, not the key range: the toy group has 18 points, and 18 = 2 · 3² is not prime, so some public keys have a tiny order. secp256k1 has a prime number of points n, so every public key other than O has order n and no mask repeats like this.

Which weakness comes from where?

The homework asks which weaknesses arise from the restricted key space and which from the toy scheme itself. They are different problems with different fixes.

WeaknessComes fromFix
key space Key found by enumerationThe deliberately small range for k.Draw k from the full group. This is the single change that removes the whole of section 5.
design Reusing the random rIf a careless implementation fixes r, the per-letter mask rQ becomes constant and the scheme collapses into a substitution cipher, which frequency analysis breaks (see the demo above).Use a fresh, unpredictable r for every message. This page draws r from a seeded generator so that every run can be repeated; a real system must take it from a cryptographic generator such as crypto.getRandomValues.
design A public key of tiny orderOn the exercise 1.1 curve the group has 18 points, which is not prime. The key k = 6 gives Q of order 3, so the mask rQ takes only three values and one of them leaves the letter in clear (see the demo above).Use a curve whose group has prime order, like secp256k1, and reject public keys of small order.
design Simple point mapMapping a byte to a point by a predictable rule leaks a little structure and limits the message alphabet.Use a standard hybrid scheme (ECIES): encrypt a random symmetric key with EC, then the message with AES.

In short, the small key space is the only reason section 5's attack works, and it is also the easiest to fix. The other points are properties of this toy construction, not of elliptic-curve cryptography itself: a properly configured scheme keeps the hard discrete-logarithm problem from exercise 1.1 and adds randomness, a safe message map and authentication on top.
